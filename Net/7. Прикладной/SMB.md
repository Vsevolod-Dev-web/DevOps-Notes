***SMB (Server Message Block)*** - Протокол работает по клиент-серверной архитектуре.
**Клиент SMB** отправляет запрос при попытке открыть на сетевом ресурсе файл или папку по [UNC-пути](UNC-путь)

**Сервер SMB** обрабатывает этот запрос, проверяя права доступа, аутентифицирует пользователя и отдаёт или записывает данные по запросу.

**Протокол использует порт 445**

Изначально протокол формировался в Windows системах, в данный момент он кроссплатформенный, реализация есть под MAC OS и Linux (Через проект Samba), а так же мобильные ОС.

**Алгоритм подключения**

1. **Согласование (Negotiation)**: Клиент и сервер договариваются о диалекте - версии SMB для дальнейшего использования функций протокола.
2. **Аутентификация (Authentication)**. Пользователь или устройство со стороны клиента подтверждает для сервера свою личность. Обычно через учетные записи Windows, NTLM или Kerberos).
3. **Подключение к ресурсу** (***Tree Connect***). После успешной аутентификации пользователь получает доступ к конкретному запрошенному ресурсу или *принтеру*.
4. **Взаимодействие с файлами** (**Request \ Response**). Пользователь взаимодействует с файлами (записывает, считывает, удаляет и т.п.) по тем же принципам и механизмам, как если бы делал это на своей машине. 

Аутентификация в SMB
Изначально, при запросе, клиент тихо отправляет данные текущего пользователя (кто отправил запрос). Если SMB сервер его не знает или у него нет прав на шару - Windows вызовет графическое окно входа.
