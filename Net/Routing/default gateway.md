**Default gateway** - это узел, как правило роутер, суть узла - быть "выходом" для сетевого трафика из локальной сети во внешние сети.

По сути, когда компьютер не знает куда направить трафик, по стандарту он направляет его на роутер, он уже разберётся. Это и есть Default Gateway.

`ip route` - показывают таблицу маршрутизации, где и указан default gateway. 
```bash
$ ip route
default via 192.168.5.1 dev wlp1s0
```
192.168.5.1 - адрес роутера. То есть, фактически в этой записи сказано *"Адреса, похожие на 0.0.0.0/0 отправляй на 192.168.5.1 от устройства wlpls0"*. То есть, направить на шлюз.

Default - это синоним 0.0.0.0/0, то есть ВСЕ возможные адреса. Но почему тогда под default не подпадают, например, адреса подсети - 192.168.5.52\24?

Тут работает правило **longest prefix match** - перед отправкой, ядро сравнивает куда отправить, и отправляет туда, где **маска самая длинная.**

- `192.168.5.52` подходит под `192.168.5.0/24` (24 бита совпадают) ✓
- `192.168.5.52` подходит под `0.0.0.0/0` (0 бит, формально совпадает) ✓

В этом сравнении побеждает подсеть с маской /24. /24 > 0.

Иначе, скажем если взять 8.8.8.8 - то этот адрес не подходит под 192.168.5.0, значит направляется на шлюз - default gateway (0.0.0.0\0)

Так же, в таблице маршрутизации можно увидеть следующую строку: 
```bash
$ ip route
192.168.5.0/24 dev wlp1s0
```
Если нужно отправить что-то в сеть, которая начинается на 192.168.5.x - то эта запись говорит компьютеру, что это текущая сеть. Не нужно передавать это на роутер, разберёмся тут. ==Так трафик не входит во вне, не идёт на **gateway**.==
