Пакетные менеджеры в Linux - это инструмент для автоматической установки, обновления и удаления ПО ([пакетов](Пакеты)), которые обеспечивают целостность системы и управляют [зависимостями](Зависимости). 

Они находят нужный софт в [репозиториях](Репозитории), скачивают его и устанавливают, заменяя ручную компиляцию и установку файлов.

Для Debian: APT (высокий уровень, frontend) + dpkg (низкий уровень, работает с .deb напрямую). APT умный: решает зависимости, интерфейс с репозиториями. 

- APT (команды: apt, apt-get, apt-cache) - удобный, handless зависимости.
- dpkg - базовый, без авто-зависимостей, но полезен для локальных .deb

Касаемо APT - в репозиторий с пакетами этого менеджера лежат пакеты софта, который проверили и залили туда на момент формирования этого репозитория. Далее, в этот пакет льют только security обновления. Это называется **stable release model**.

У пакетного менеджера, при использовании его для установки есть опция `-y`.

Простая опция которая отвечает `y` на "вопрос" при установки - `Do you want to continue? [Y/n]`

Это имеет смысл использовать в Dev среде или при инициализации голого сервера для автоматизации (Например при раскатки в CI\CD пайплайнах).

Но с этим нужно быть аккуратно в Prod среде. Это опасно по следующим пунктам:
1. **Момент не контролируемый.** Пакет устанавливается прямо сейчас, без тестирования, без окна обслуживания.
2. **Нет отката.** Когда накатишь, что-то не то, откатить не получится, проблемы уже начались.
3. **Может подтянутся что-то неожиданное.**


Некоторые службы могут работать на legacy зависимостях или пакетах. Для безопасности обычно устанавливают следующим образом:

```bash
apt install <пакет>=<версия>
```
