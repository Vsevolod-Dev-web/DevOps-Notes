***PXE*** - это спицификация описанная в прошивки сетевой карты для сетевой загрузки и раскати ОС.

Это набор протоколов, где ОС ставиться и 90% нагрузки приходится на сеть.

Когда на ПК не стоит система, то **прошивка** его сетевой карты **кричит в сеть** запрашивая что-нибудь загрузить.

### Алгоритм работы
1. ПК загружается.
2. Прошивка **сетевой карты** запрашивает IP
3. [DHCP](DHCP) сервер даёт IP. Так же, он говорит, отвечая на запрос - **сходи на такой-то сервер**, скачай оттуда файл.
4. Сетевуха качает этот файл (загрузчик) по [TFTP](TFTP)
5. Запускет этот файл - [NBP](NBP.md) (На этом работа PXE полностью заканчивается)
6. И PXE Умирает

При этом, этот файл - это не образ и не система. Это лёгкая программа килобайт на 50.
Эта программа - это загрузчик, который уже грузит систему в ОЗУ.

В зависимости от режима (BIOS vs UEFI) реализация PXE (PXE-клиент - программа) живёт либо на сетевой карте (BIOS) либо в прошивке материнки при этом используя драйвер сетевухи (UEFI).

# PXE и iso образ
PXE не тянет по сети [iso-образ](iso%20образ). Из него берутся отдельные части, лежащие на [веб-сервере](Веб%20Сервер).

Конечно, можно тянуть целый образ, но обычно это делают с лёгкими - так как его нужно загрузить в ОЗУ.

Есть схемы, где ISO действительно едет по сети целиком: iPXE умеет `sanboot` — подсунуть образ как виртуальный диск по iSCSI или HTTP, и машина думает, что в неё вставили CD. На этом построен iVentoy.

Так вот, PXE - тянет[ куски образа](ISO%20образ) по HTTP или TFTP, и это может быть файл с автоответами.


И самый последний источник - самый тяжелый.


В итоге, как всё выглядит:
```
Сетевуха (PXE) качает по TFTP загрзчик (Спросив у DHCP откуда) ->
Загрузчик (NBP - например iPXE) по HTTP качает ядро и intird ->
initrd отдаёт адрес ответника -> 
Инсталятор качает ответник и репозитории ->
Система поставилась
```
